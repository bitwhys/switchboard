# @switchboard-dev/core

## 0.1.0

### Minor Changes

- [#68](https://github.com/bitwhys/switchboard/pull/68) [`ddbc144`](https://github.com/bitwhys/switchboard/commit/ddbc144a3391d5bfd1475f2ab902a73260265a9e) Thanks [@bitwhys](https://github.com/bitwhys)! - Kernel spec §10: the activation-time capability check — at most one installed provider per capability name (`duplicate-provider`), the once-per-plugin check before `setup` with near-miss version diagnostics (`capability-unsatisfied`), real semver range-grammar validation of `requires` entries, and the `manifest-drift` warning when a registered service name appears in no plugin's `provides`.

- [#72](https://github.com/bitwhys/switchboard/pull/72) [`b056780`](https://github.com/bitwhys/switchboard/commit/b056780ac47972c98eac68bf47bc8edfe8684ec9) Thanks [@bitwhys](https://github.com/bitwhys)! - Kernel spec §11 + §16–§18: the host surface — public `createSwitchboard` with the synchronous construction contract (`plugins` array as activation order, `ready` that never rejects, `dispose()` as full teardown plus announce retraction, the `invalid-options`-only throw envelope); the instance as a full host door with `host`-attributed acts; the `globalThis.__SWITCHBOARD__` handoff (order-independent push/subscribe, `retract`/`onRetract`, first live kernel wins with a `duplicate-kernel` dev-mode warning); `commands.observe` full-array snapshots driven by §11's tracked-read `when` evaluation; and `plugins.list()` — both read surfaces on both doors, grant-agnostic.

- [#64](https://github.com/bitwhys/switchboard/pull/64) [`9a28b40`](https://github.com/bitwhys/switchboard/commit/9a28b40f8c0c7062d3a61f9b131a83508d171469) Thanks [@bitwhys](https://github.com/bitwhys)! - Kernel spec §2–§4: the name grammar and name kinds, `definePlugin` with manifest validation, and the activation lifecycle with Disposable teardown — plus the diagnostics machinery they lean on (`SwitchboardError`, the kernel diagnostics channel, dev mode, and the default console reporter).

- [#66](https://github.com/bitwhys/switchboard/pull/66) [`db1a331`](https://github.com/bitwhys/switchboard/commit/db1a3314cbf7072dfbb51c6dde9b5d5eb4e77a2a) Thanks [@bitwhys](https://github.com/bitwhys)! - Kernel spec §5–§9: `PluginApi` grouped by primitive, Commands with pre-dispatch `validate` and structured invocation errors, strictly-ephemeral Events, Context with synchronous replay on observe, and Services whose `get` resolves the moment the provider registers and rejects immediately when no installed plugin provides the capability.

- [#70](https://github.com/bitwhys/switchboard/pull/70) [`17c312b`](https://github.com/bitwhys/switchboard/commit/17c312b04ca0d960f5189ee5de8e84afac19061a) Thanks [@bitwhys](https://github.com/bitwhys)! - Kernel spec §13: per-plugin storage — `api.storage` as the async JSON-valued area with invisible namespacing, the public `StorageEngine` interface plus the two shipped engines (`localStorageEngine`, key-prefixed and the default, with automatic `memoryEngine` fallback when `localStorage` is missing or throws; `memoryEngine`, Map-backed and non-durable), and the enforced default-closed `storage:use` gate rejecting loudly with `permission-denied`. The `storage` option threads through kernel construction with an `invalid-options` structural gate.
